# 多模型子代理协作

本技能只规定下发协议。任务分类、拆分、各类型系统提示词、任务粒度与事实标注以仓库根目录的 `multi-agent-design.md` 为准；每类任务的 `provider`、`model`、`reasoning_effort` 以 `multi-agent-routing.base.yaml` 为准。发生冲突时，优先级为：用户指令 > 上述两份文件 > 本技能。不得用本技能中的示例覆盖两份依据文件的实际配置。

## 主代理角色边界

主代理仅负责协调：读取并整理获准提供的上下文、分类与拆分任务、准备任务稿、询问确认、查找或创建通道、监控进度、核对交付物、按通道原样展示结果，以及在明确授权后按约定保存原文。

主代理不得代替子代理完成专业内容工作，不得融合多份答案、补写专业结论、改写或修正文案来覆盖子代理原文。发现内容问题、事实缺陷或冲突时应原样指出并交用户决定；需要补充或重发任务时，重新提交任务稿并取得用户确认。

## 分类、拆分与路由

1. 按 `multi-agent-design.md` 第二节的主要交付物规则和优先判定顺序分类，命中即停；不得按过程中使用的工具或操作分类。
2. 多个独立交付物拆成多个任务。每个任务应可由一个模型在 1–3 分钟内完成；超出时继续拆分。
3. `default` 不是任务类型。遇到无法归入九类的任务时，先向用户说明并询问是否建立兜底通道；未经确认不得按 `default` 创建或派发。
4. 每类任务从 `multi-agent-routing.base.yaml` 读取对应 code 的 `provider`、`model` 和 `reasoning_effort`。创建通道前用 `list_subagent_models` 核对该路由及档位是否可用；不可用时如实报告，不擅自换模型或档位。
5. 每个任务稿必须包括该类型在 `multi-agent-design.md` 第三节中的系统提示词，逐字原文照录，不得改写、删节或用主代理自己的提示词替代。
6. 任务稿同时写明任务类型 code、routing 命中的 provider/model/effort，以及只读或可写范围。

## 每次下发确认与任务稿

每次下发都必须先获得用户确认，无例外：首次调用 `subagent`、通过 `send_message` 发送业务任务、发送冒烟测试、补充任务或重发任务均须确认。先向用户展示完整任务稿、拟用通道、各通道交付物和允许写入的位置；确认后才执行对应下发。用户说“修正后下发”，仅授权按其指定修正执行，不得夹带其他修改。

任务稿必须清楚区分以下四类信息；没有内容的类别写“无”：

1. **用户原话**：保留与本轮任务有关的原始要求，不把主代理推断写成用户原话。
2. **已确认要求**：任务、交付形式、约束、只读或可写范围，以及用户已确认的修改。
3. **背景说明**：理解任务所需资料和语境，不自动成为必须执行的要求。
4. **待确认建议**：主代理提出但尚未获批的调整；未经确认不得作为执行要求下发。

背景不得升级为硬约束。用户只批准删除某条要求时，不得自行增加反向禁令。对子代理不可见的必要上下文，应在任务稿中补齐获授权提供的材料，不依赖子代理猜测。

## 通道创建、复用与显示名

- 九种任务类型各自使用一条通道。即使两类任务映射到相同的 provider/model/reasoning_effort，也不共用通道；同一模型的不同 reasoning_effort 更是不同通道。通道创建时档位固定，之后 `send_message` 续期不会改变档位。
- 本 harness 的 `subagent` 工具不提供后台运行参数；每次调用直接返回可续期的 id，使用 `send_message` 以该 id 续期，这就是通道。不得要求或传入该工具不支持的参数。
- 先用 `list_agents` 查看已有可续期通道。复用时必须按通道对应的任务类型、路由和档位匹配；不得因模型相同就跨类型共用。续期只用工具返回的 subagent id，不从显示名推定。
- 建立新通道前，先询问用户要建立哪些**任务类型**的通道（可多选，也可均不选），仅创建用户明确选中的类型。不得问用户从模型候选清单中选模型，也不得默认把九类全部建好。
- 建通道前调用 `list_subagent_models`，核对 routing 指定的 provider/model/reasoning_effort。路由或档位不可用时如实告知用户，不换路由。
- `description` 使用短模板 `模型｜类型`，例如 `Claude-Opus-5-5｜设计`、`DeepSeek-V4.1-Flash｜检索`。具体任务内容放在下发消息中；显示名不是通道标识，也不能通过 `send_message` 修改。
- `opencode/claude-opus-5-5` 必须显式指定 reasoning_effort；base routing 的 `design` 对应 `high`。创建时按 routing 核对并传入该档位，续期沿用创建时档位。
- 相互独立且已获用户确认的下发可在同一助手消息中并行执行；不得为等待结果重复启动同一任务。

## 首次建通道的冒烟测试

建立新通道时执行冒烟测试；已有匹配的可续期通道直接复用，不为重复测试另建通道。先按上文询问用户选择要创建的任务类型，并展示拟建通道的 provider/model/reasoning_effort、`模型｜类型`显示名和以下完整测试任务；获得确认后再创建通道并发送测试：

> 这是一次工具执行冒烟测试，只做以下事项：
> 1. 用 bash 执行 `echo hello-world`。
> 2. 只回复一行 `TOOL-OK: hello-world`。
> 不要创建、修改、删除任何文件，不要执行其他命令。

用户选中的多个类型分别创建各自通道，各自执行测试。保留并核对每条通道返回的可续期 id 与测试结果；后续仅在用户确认后通过相应 id 续期下发业务任务。

## 事实标注与交付

要求子代理按 `multi-agent-design.md` 第五节及其中共同约定使用四类事实标签：**用户确认前提**、**材料明确记载**、**目标或预估**、**待核实**。各标签的定义以该文件为准；不在本技能中重复解释或另行定义。主代理保留各通道原有标注，不补写专业结论；事实标注缺失或证据冲突时原样指出，交用户决定是否追加溯源任务。

默认在对话中交付。按通道分块原样展示各自返回，不融合、不改写；必要时另列不超过三条关键点提示。用户要求落盘时，具体文件路径与写入权限必须写入任务稿并经用户确认；用户只要求对话回复时，不扩大写入授权。

## 产物落盘

模型输出写入工作区 `.dsh.local/multi-subagent/`。写入前同时核验目标路径：

- 执行 `git check-ignore -v --no-index -- <目标路径>`，确认命中的忽略规则。
- 执行 `git ls-files -- <目标路径>`，检查该具体文件是否已被 Git 追踪。已追踪或无法确认时，先报告，不写入。

不得修改忽略规则或移除追踪来绕过检查；需要调整时交用户决定。

原文文件名格式为：

`<主题>-<provider>-<model>-raw.md`

各通道文件必须不同；若目标文件已存在且需保留，可加不含目录分隔符的区分后缀，并在任务稿中写明具体路径。子代理只写获授权的文件，不覆盖其他通道结果；仅获建议输出权限时不得修改源文件或其他文件。主代理获准代为保存时，只复制返回原文，不润色覆盖；保存后仍按通道原样展示，不改为融合答案。

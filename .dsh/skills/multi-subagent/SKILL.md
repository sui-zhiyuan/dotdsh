# 多模型子代理协作

主代理负责协调，各子代理独立处理任务内容。用户决定采用哪份建议；主代理不得代替用户融合或改写答案。

## 主代理角色边界

### 可以做的协调动作

- 读取用户指定的最新文件和输入，整理需要下发的上下文。
- 整理任务稿，检查用户是否已确认本次下发内容。
- 查看可续期子代理，选择可用通道，执行已确认的下发。
- 监控任务进展、收集返回、核对交付项目是否齐全。
- 分块展示各通道原文，必要时提供不超过三条关键点提示。
- 检查获授权的落盘路径，执行原文保存等协调动作。

### 禁止做的内容工作

- 不替子代理完成任务本身或进行专业推理。
- 不融合多份答案，不自行补写专业结论。
- 不自行修正子代理文案，也不以主代理的修改覆盖返回原文。
- 不把内容缺陷悄悄改成正确答案；原样标识问题，交用户决定如何处理。需要补充任务时，重新提交任务稿请用户确认。

## 任务稿与每次下发确认

**每次下发都必须先获得用户确认，无例外。**首次调用`subagent`、通过`send_message`下发业务任务、发送冒烟测试、补充任务、重发任务，均遵守此规则。

先展示本次准备发送的完整任务稿，以及拟使用的通道、各通道交付物和允许写入的位置；用户确认后，才执行相应下发。用户说“修正后下发”，即视为对该指定修正的发布授权，按修正内容执行，不擅自夹带其他修改。

任务稿必须清楚区分以下四类信息，没有内容的类别写“无”：

1. **用户原话**：保留与本轮任务有关的原始要求，不将主代理推断伪装成用户原话。
2. **已确认要求**：写明本轮任务、交付形式、约束、只读或可写范围，以及用户已确认的修改。
3. **背景说明**：帮助理解任务的资料、语境和解释，不自动成为必须写入答案的要求。
4. **待确认建议**：主代理提出但尚未获批的调整，明确列出，未经确认不得作为执行要求下发。

背景说明不得升级为硬约束。**用户只批准删除某条要求时，不得自行增加反向禁令**：删除“必须写某内容”，不等于新增“禁止写某内容”；删除“不得写某内容”，也不等于新增“必须写某内容”。

对子代理不共享的上下文，任务稿须自行补齐用户授权提供的必要输入，不依赖子代理猜测。

## 命名与通道复用

### 命名规范

创建`subagent`时，`description`使用短模板：

`模型｜角色`

例如：

- `GPT-6.1-Sol｜OKR顾问`
- `DeepSeek-V4-Pro｜OKR顾问`

**具体任务不写入`description`**，放入下发消息。显示名创建后不可修改；不要承诺通过`send_message`改名。

### 轻量复用原则

先用`list_agents`查看已有可续期通道；可用则用`send_message`复用，不因更换具体任务而默认新建。

需要首次建立通道时，先按下一节确认用户要创建哪些模型的子代理，不得按模型清单默认全建；再按用户指定的provider/model选择路由，并使用`list_subagent_models`查看可用信息。无法使用指定路由时，如实报告，不擅自换成其他模型。

相互独立且已获用户确认的下发，在同一条助手消息内并行执行；业务通道采用后台子代理，不为等待返回而重复启动同一任务。

## 首次建通道的冒烟测试

冒烟测试并入本技能，建立新通道时执行；已有可用通道直接复用，不为重复测试另建通道。

### 先确认要建哪些模型

下表是**可选清单，不是默认全建清单**。建通道前先把整张表展示给用户，逐个询问要创建哪些 module 的子代理（可多选，也可一个都不选）；只对用户明确选中的 module 建通道并跑冒烟测试。

- 用户未点名、也未回答时，**一个通道都不建**，继续等待确认。
- 用户只选中其中一部分时，只建这部分；未选中的 module 保持未建，不预先创建备用通道。
- 用户点名清单外的 provider/model 时，先用`list_subagent_models`核对该路由与其推理档位，再并入本次确认。

| # | provider | model | reasoning_effort |
|---|---|---|---|
| 1 | `opencode-gpt` | `gpt-6.1-sol` | 可选 |
| 2 | `deepseek-official` | `deepseek-v4-pro` | 可选 |
| 3 | `opencode` | `claude-opus-5-5` | **必填**，建议`high` |

### `claude-opus-5-5` 必须显式指定推理档位

`opencode/claude-opus-5-5`是只接受自适应思考的模型，**每次`subagent`调用都必须显式传入`reasoning_effort`**（`low`、`medium`、`high`、`xhigh`、`max`之一），不得省略：

- 省略档位时，pi-ai 会发送`thinking:{"type":"disabled"}`，上游 opencode Zen 直接返回 400：`"thinking.type.disabled" is not supported for this model. Use "thinking.type.adaptive" and "output_config.effort"`。
- 现象是子代理零 token 就失败、重试同样失败；这不是网络或鉴权问题，补上档位即可恢复。
- 档位随通道保存：`send_message`复用已有通道时沿用创建时的档位，不需重传；新建通道必须重新指定。
- 冒烟测试同样适用：向用户展示的拟建通道必须写明`reasoning_effort`的取值。

### 首轮：工具执行

向用户展示拟创建通道的provider/model、`reasoning_effort`（`claude-opus-5-5`必填）、`模型｜角色`显示名及以下测试任务，获得确认后再创建后台子代理：

> 这是一次工具执行冒烟测试，只做以下事项：
> 1. 用bash执行`echo hello-world`。
> 2. 只回复一行`TOOL-OK: hello-world`。
> 不要创建、修改、删除任何文件，不要执行其他命令。

需要创建多个独立通道时，仅在用户已选中的 module 范围内、取得确认后并行创建。留意工具返回，收到结果后检查是否完成指定命令及回复。

## 事实等级与证据性质

在任务稿中要求子代理对返回中涉及的事实、前提及数值使用以下标注，正文旁标注或附简短事实说明均可：

- **用户确认前提**：用户明确指定本轮采用的前提，注明是用户确认，不改称独立验证结论。
- **材料明确记载**：可定位到文件、章节、行号或其他具体来源的原文记载；只说明材料写了什么，不扩大其适用范围。
- **目标或预估**：拟议目标、挑战值、估算及材料中的预期收益，不当作已完成结果。
- **待核实**：来源不足、存在矛盾或无法确认的断言，保留不确定性。

事实性质不确定时标“待核实”。不得把目标改写成实测，不得把基准场景改写成客户生产采用；多个模型结论一致或引用同一材料，也不自动升级为已核实事实。

主代理保留各通道的标注，不自行补写专业结论。缺少标注或证据冲突时，原样标识并交用户决定是否追加溯源任务。

## 输出规范

- 按通道分块原样展示各自返回，**不融合**。
- 必要时另加**不超过三条关键点提示**。

## 产物落盘

模型输出写入工作区的`.dsh.local/multi-subagent/`，具体文件路径及写入权限写进任务稿并经用户确认。用户要求只在对话中返回时，不自行扩大写入授权。

### 写入前检查

路径命中忽略规则，不等于文件未被Git追踪。落盘前同时核验：

- 用`git check-ignore -v --no-index -- <目标路径>`确认命中的忽略规则。
- 用`git ls-files -- <目标路径>`检查该具体文件是否已被追踪；已追踪或无法确认时，先报告，不写入。

不得通过修改忽略规则或移除追踪来绕过检查；需要调整时交用户决定。

### 文件命名与写入边界

原文文件名使用：

`<主题>-<provider>-<model>-raw.md`

例如：

`okr-review-opencode-gpt-gpt-6.1-sol-raw.md`

文件名必须含provider、model及`raw`原文标记。各通道的目标文件必须不同；若已有文件需保留，可加不含目录分隔符的区分后缀，并在任务稿中明确具体路径。

- 各通道只写获授权的各自文件，禁止覆盖别家结果。
- 子代理仅获建议输出权限时，不得修改任务涉及的源文件或其他文件。
- 主代理获授权代为保存时，只复制返回原文，不润色覆盖。
- 原文不可被主代理的总结、专业判断或改写稿覆盖。
- 落盘结果仍按上述输出规范展示，不因保存文件而自行改为融合答案。
